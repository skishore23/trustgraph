# Delegate an 8090 work order to TrustGraph

The intended flow is: an 8090 agent submits an operator-admitted task to
TrustGraph, polls the result, requests a fresh repair if access restrictions
block it, then hands the exact output to a human reviewer. TrustGraph owns
generation, source capture, policy checks and publication.

Connecting Codex to 8090's MCP server is the opposite direction: it lets Codex
read 8090 work orders. It does not give 8090's hosted agent access to TrustGraph.

## Run the local Codex demo

The [demo launcher](../scripts/8090_demo.py) uses Codex's authenticated MCP
connections to read an 8090 work order and submit its admitted Summary to
TrustGraph. It runs the Risk-context case, waits for the access block, requests
a fresh shared-source repair and moves the 8090 work order to **In Review**
when the repair passes its checks. It leaves approval and publication to the
operator. It uses an ephemeral Codex transport context without starting an
outer model turn; TrustGraph starts and captures the actual generation.

Start the live gateway and register both MCP servers in Codex, following
[live setup](../../../../docs/development.md) and [agent integration](../../../../docs/agent-integration.md).
Authenticate the Factory connection with `codex mcp login <server-name>`.
Create a private 8090 project and a work order whose `## Summary` section
contains the exact text of [work-order.txt](../../../bankcase/work-order.txt).
Keep the work order's other sections outside that Summary.

Save machine-specific settings in ignored `.trustgraph-live/8090/demo.json`:

```json
{
  "factory_server": "software-factory-your-server-name",
  "project_id": "your-8090-project-id",
  "work_order_id": "WO-1",
  "github_repository": "your-account/private-workbench"
}
```

With Python 3.9+ and the configured Codex CLI, run from this checkout:

```sh
python3 examples/integrations/composio-github-issues/scripts/8090_demo.py run
```

Run the same command to resume the recorded jobs; it does not create a new pair
on each invocation. The ignored `run.json` file records mutation attempts
before dispatch, IDs and results. A lost mutation reply stops the launcher
until the operator inspects the workspace, rather than automatically resubmitting.
One launcher may own the run file at a time. `python3 examples/integrations/composio-github-issues/scripts/8090_demo.py status`
prints the recorded IDs and review URL; open that URL for current live status.

This local path requires no tunnel or additional API key. It uses the configured
Codex `app-server` MCP interface, tested with the local CLI during setup.
The launcher verifies the Summary and workspace repository before submission;
it does not import arbitrary 8090 documents as new captured sources.

## Start the gateway and HTTP MCP adapter

Configure the live workspace using [development.md](../../../../docs/development.md), then run:

```sh
cargo build --locked -p trustgraph-cli
./target/debug/trustgraph start
```

In another terminal, create a separate capability for the remote agent. Store
it in ignored local state, with owner-only permissions:

```sh
python3 - <<'PY'
import os, secrets
from pathlib import Path
directory = Path('.trustgraph-live/8090')
directory.mkdir(parents=True, exist_ok=True, mode=0o700)
fd = os.open(directory / 'remote-token', os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w') as output:
    output.write(secrets.token_hex(32))
PY
```

Run token creation once. To revoke access, stop the adapter, replace the remote
token and restart it. It must differ from the local agent token. Neither token
belongs in a prompt or a committed configuration.

Expose a separate adapter port through your HTTPS tunnel, for example:

```sh
ngrok http http://127.0.0.1:8083 --inspect=false
```

Use the returned HTTPS **origin** as `--public-url`. Replace the local token path
with the `agent-token` inside your configured live state directory:

```sh
./target/debug/trustgraph mcp-http \
  --url http://127.0.0.1:8080 \
  --token-file /absolute/live-state/agent-token \
  --access-token-file /absolute/TrustGraph/.trustgraph-live/8090/remote-token \
  --public-url https://your-tunnel.example \
  --port 8083
```

Only the adapter port goes through the tunnel. Keep the operator workspace on
loopback port 8080. The adapter serves `/mcp` and exposes the same five tools as
the [stdio adapter](../../../../docs/agent-integration.md). Every HTTP request requires
`Authorization: Bearer <remote-token>`. It rejects browser Origin headers and
unexpected Host headers. Backend requests stay on loopback and do not follow
redirects or automatically retry submissions.

The adapter is stateless and supports JSON responses over Streamable HTTP.
Review URLs still point to the local operator workspace; the reviewer opens
them on the machine running TrustGraph. They are not remote operator sessions.

## Register the endpoint with 8090

| Setting | Value |
| --- | --- |
| Name | TrustGraph |
| Transport | Streamable HTTP |
| URL | `https://your-tunnel.example/mcp` |
| Authentication | Bearer token from the private `remote-token` file |

8090 documents catalog connections and per-tool permissions under
[MCP Servers](https://docs.8090.ai/connections/mcp-servers). The organization UI
inspected during setup showed a Composio connector catalog and organization
access controls, without a field for registering an arbitrary MCP URL. A direct
hosted-agent demo still needs a supported custom connector registration path
from 8090. An Admin API key by itself does not establish that support.

Once registered, permit workspace/status reads and enable submit/repair/simulate
as appropriate for the demo. Approval, publication and policy activation are not
available through this adapter.

## Demo prompt

Use the exact text from [work-order.txt](../../../bankcase/work-order.txt)
when submitting. New goal text must first be admitted by the operator.

> Inspect the TrustGraph workspace. Submit the admitted payment-reconciliation
> work order with `include_risk: true` exactly once and retain its ID. Poll
> `trustgraph_status` until generation finishes. If the decision blocks sharing
> restricted Risk-derived output with Engineering, call `trustgraph_repair`
> once for that ID and poll the new work item. Report each policy decision and
> the final human review URL. Hand review and publication to the operator.

If a mutation reply is lost, inspect existing work before trying again. The
task API does not offer idempotency keys.

## Local coding-agent demo

A coding agent on the same machine can use both the 8090 connection supplied by
the organization and TrustGraph's existing stdio connection. Register the latter
using [agent-integration.md](../../../../docs/agent-integration.md). The coding agent reads a work
order from 8090, delegates the admitted task to TrustGraph and reports the review
URL. This works without a public tunnel, but the caller is the local coding
agent rather than 8090's hosted agent. Importing arbitrary 8090 documents into
TrustGraph's captured source set requires an additional source adapter; this
demo uses the committed bank-case sources.
