# Agent-facing MCP Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans in the current session, with independent final review.

**Goal:** Make the consulting workflow usable through real MCP and document a practical 8090 companion-agent integration.

**Architecture:** One journal owner serves both web UI and authenticated loopback MCP. A Rust SDK stdio bridge forwards only the same named tools. Domain calls reuse the app router as demo-agent.

**Tech Stack:** Rust, rmcp 3.10.0, Axum, Tower util, existing Tokio and JSON.

**Spec:** docs/superpowers/specs/2026-11-14-mcp-design.md

## Global constraints

- No model-callable approval, raw publish or identity override.
- No external deployment, 8090 writes or user-wide configuration mutations.
- Preserve single writer, idempotency and snapshot checks; stdout is protocol only.
- Distinguish synthetic local qualification from live 8090 document integration.

## Review focus

- Agent identity injection: unknown params rejected, human tools absent and unknown calls rejected.
- Transport credential leakage: private token never printed, no redirects/proxies, loopback URL validation.
- Repeated tool calls: same preparation key reuses the same review; drift and blocked plans have no generation effect.
- UI continuity: the review created by MCP can be approved through the same app and status reflects actual delivery.
- Integration uncertainty: 8090 catalog documentation is not proof of arbitrary custom server registration.
